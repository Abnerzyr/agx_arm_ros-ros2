# AGX NERO 货架抓取-放置系统 · 核心算法与系统架构

> AGX NERO 七轴机械臂 + AGX 夹爪 + RealSense，"货架分层取放"（车-臂协同）。本文聚焦三大核心：**取放主流程（粗/精两级对准 + 夹取）**、**视觉识别与过滤算法**、**轨迹规划与上下层通信**。
>
> 关键源码：`shelf_workflow_node.py`（编排）、`grasp_executor.py`（执行）、`yolo_grasp_node.py`（视觉）、`place_planner.py`（放置）、`agx_arm_ctrl_single_node.py`（CAN 底层）、`moveit2_local.py`（MoveIt 封装）、`start_arm_prod.sh`。

---

## 1. 系统链路（五层）

```
车端调度 ─ /arm/task_command(层) · /arm/release_command · /arm_task_report(JSON) ─┐
shelf_workflow（编排：两级对准/检测锁定/上报）                                      │
   ├─ vision_gate            yolo_grasp（检测→3D抓取点/碰撞盒/点云）                │
   ├─ grasp_target_cmd etc   grasp_executor（抓/放状态机，力反馈夹取）              │
   └─ MoveIt2（/move_action 规划、/apply_planning_scene、octomap）
MoveIt2 → ros2_control JTC(200Hz 插值) → /control/joint_states
agx_arm_ctrl_single_node（控制门 + CAN 1Mbps）→ pyAgxArm → 伺服/夹爪
```



## 2. 取放主流程：粗对准 → ArUco 精对准 → 判别夹取（关键）

比赛对取放的要求是"**先到大概位置（粗对准符合），再据 ArUco 位姿精对准并夹取**"。系统严格采用两级收敛，且**精对准以 ArUco 码作为位姿正确与否的裁判，合格才夹取**。

```
task_command(层)
 └ NOMINAL_POSE 粗对准：直达该层标定关节位（LAYER_COARSE_JOINTS，视野摆正、码入视野）
     └ ALIGN ArUco 精对准：闭环伺服把相机光轴对准码，收敛判据通过 = 位姿正确
         └ WAIT_DETECT 视觉锁定：目标合理性(几何窄带)连续3帧 → 锁死不再重测
             └ 抓取预备位（LAYER_PRE_GRASP_JOINTS，目标正前方等高）
                 └ TRIGGER_GRASP：先下发已确认位姿(grasp_target_cmd)再触发
                     └ executor：验证→直线接近→到位→力反馈合爪→(提拉防滑)→分级回退回 home
                         └ 上报 PICK 成功(已收回) → 等 release_command → PLACING → 上报 PLACE
```

### 2.1 粗对准（NOMINAL_POSE）
无在线感知，运动到**每层标定关节位**，只解决"把物体与码纳入视野"的定位先验；重复性由关节精度保证。到位 = executor IDLE ∧ MoveIt 到位。现场可用 `preset_home` 话题切为 home 预置位联调。

### 2.2 ArUco 精对准（ALIGN）——位姿闭环
目标状态：**目标码在相机前方 `align_dist=0.4m`、码心投影于画面中心**。以 `aruco_opencv_msgs/ArucoDetection`（4X4_50，码 50mm）为输入迭代收敛：

1. **按码过滤**：只认当前层绑定的 id 且 1s 内新鲜检测（`_fresh_target_marker`）——保证伺服对象永远是"本货位的码"。
2. **世界坐标重建**：码中心变换到 base 系，其 z 兼作桌面参考高 `_table_z`。
3. **看码位姿反解**：在码后方 `align_dist` 处以"视线方向构造旋转、滚转约束到世界竖直（防腕翻）"，再乘 相机←TCP 安装变换得目标 TCP 位姿（矩阵链 `目标TCP = 相机目标 × (相机←TCP)`）。
4. **判位收敛（安全闸门）**：`_align_verified` 三条件同真才认为位姿正确——
   - 码距相机 `‖(x,y,z)‖ ≈ align_dist`（容差 0.05m）；
   - 归一化投影 `|x/z|、|y/z| ≤ 0.05`（码在画面中心）；
   - 深度 `z > 0.05m`。
5. 未收敛 → 按误差 `move_to_pose` 纠偏（关节停稳后再发下一动），至多 `align_max_iter` 次；持续无码 → 回 home 自动重跑完整流程（预算内重试）。

> **重点**：精对准完成后夹取不是盲目执行——**只有 ArUco 码 id 匹配、且其空间位姿满足"标定距离 + 投影居中"的几何条件时，才判定位姿正确并放行后续检测与夹取**；否则继续纠偏/重试。这一 ArUco 判别是整套取放的安全闸门。

### 2.3 检测锁定与夹取触发
- **合理性门控**：目标水平距离须在可达半径内；z 须落在"预备位 tcp 高度 + 中心偏移 ± 容差"窄带（无码时替代桌面参考），防假目标/远点。
- **多帧确认**：新鲜目标盒 + 新鲜抓取位姿 + 合理性**连续 3 帧**才"锁死"（`_confirmed_grasp_pose`），锁定后预备位/直线接近一律用锁定值，杜绝触发瞬间锁到漂移帧。
- **触发竞态消除**：先经 `grasp_target_cmd` 下发已确认位姿，再由 `manual_grasp_start` 触发，executor 在 2s 内优先采用该确认值。

### 2.4 力反馈夹取（grasp_executor）
夹爪闭环基于 `/feedback/gripper_status`（宽度 m + 力 N）：
- **到位判定**：TCP 误差连续 3 次 ≤ 容差（含 1s 冷却），超时记失败。
- **合爪判夹持**：`close()` 后"力 > 阈值连续 3 tick"或"宽度进入 ±2mm"即闭合完成；**holding = 宽度未完全闭拢(>5mm 有物体) ∧ 力持续**——抓没抓住由宽度+力联合证据判定，不靠指令猜。
- **提拉防滑（可选）**：握持后抬升悬停，宽度漂移超阈值或力跌落连续多次即判滑落，杜绝"没夹稳就带走"。
- 结果语义 `grasp_result`：0=未执行/抓前失败、1=空抓、2=已握持。**空抓 1 按失败处理并触发重试**，杜绝空爪误放。
- 收臂采用**分级回退**：抓取预备位→粗对准位→home（workflow 通过 `grasp_retract_path` 下发），异常位收臂不直冲 home，防横扫碰撞；握物后先移除目标盒再清 octomap 后回 home。

## 3. 视觉识别与过滤算法（yolo_grasp_node）（关键）

```
RGB+D+内参
 → 门控(vision_gate / 关节稳定 / 深度新鲜)
 → YOLOv8s-world 检测
 → 有效框过滤：深度 P10~P90 跨度 ≥ 20mm（剔除扁平假目标：贴墙码纸/货架面）
 → ArUco 关联选物：含码像素或距码 ≤8px 的框剔除；选"离码最近"的非码框（语义=本货位物体）
 → 20% margin 方形裁剪(copyMakeBorder 补边)
 → 桌面掩膜 + 连通域选物 + 深度修复(inpaint)
 → GR-ConvNet(质量/角度/宽度) 分级回退 → 顶面足迹质心=抓取点
 → 桌对齐 3D 碰撞盒 + 目标冻结 → TF→base_link → /grasp_pose /yolo/target_box /yolo/table_height
```

### 3.1 物体分割（RANSAC + 掩膜 + 连通域）
- **平面锁定自纠正**：拟合失败 / 目标移动 >100px / 锁定 >30s / 上帧掩码为空 → 强制重拟合，并做合理性校验（拒绝偏高、非水平平面，防把物体滤掉）。
- **"种子 vs 最高分量"选物**：以 YOLO 框中心为种子做 8-连通域；种子分量高度足够则保留，否则退选**全场最高分量**（而非最大面积）——避免种子落在桌面时把大桌面误当物体、抓取点飞走。
- **深度修复**：无效深度先 inpaint(TELEA) 再入网，保证网络输入完整。

### 3.2 抓取点 = 顶面足迹质心+斜视矫正
斜视下 GR-ConvNet 的 argmax 像素会横向偏 ~6cm，故**位置不再用网络像素**：
- 取物体顶面高度带内的点 → 沿平面法向投影回桌面得到完整"足迹" → 足迹 2D 中位 + `max_hgt/2` 沿法向抬高 = 抓取点；顶面带为空时回退"全可见点中位 + 高度修正"。
- **角度仍取网络预测**，宽度限幅 [0,0.1m]。
- **合理性闸门**：质心高须 > 最小抓取高且像素回投在框内，否则丢帧（保留上帧锁定点）。

### 3.3 GR-ConvNet 分级回退
掩码内质量 argmax → 质量不足放宽到连通域内 → 再放宽到全图 → 退框中心。保证"几乎总有输出、又优先掩码内高置信点"。

### 3.4 桌对齐 3D 包围盒（规划碰撞盒）
物体点在 base 系沿"桌面法向 n + 桌面切向 e1/e2"正交基做 2%/98% 分位包围盒（尺寸+朝向），使盒贴合真实物体而非相机轴；**最近深度带高度补全**防顶面稀疏时盒塌成薄片；经 `box_padding` 外扩后作为 executor 规划场景碰撞物（2s 内须配对）。

### 3.5 目标冻结与桌面高度
- **lock**：抓取点+盒连续 N 帧在容差内即"锁死"持续发布，目标移动才重锁，抗单帧跳变。
- 以 RANSAC 平面解算抓取点所在桌面高度发布 `/yolo/table_height`，executor 用它替代盒底算抓取偏移（更准）。

### 3.6 点云"只挖洞"策略
全景点云供 octomap；带目标时仅剔除物体真实轮廓（或外扩矩形），并用**外部真实桌面点重拟合把洞补平**——重建 octomap 在物体周围不"少一圈"，为直线接近/放置留出干净场景。点云/推理均受门控，运动中不采帧（防斜云、防脏图入 octomap）。

## 4. 轨迹规划与运动执行

### 4.1 MoveIt2 封装（moveit2_local.py）
统一封装三类后端：MoveGroup action `/move_action`（位姿/关节）、`/apply_planning_scene`（碰撞盒增删）、`/compute_cartesian_path` + `arm_controller/follow_joint_trajectory`（笛卡尔执行）。
- **位姿目标**：目标点包成半径 1cm 的球 BoundingVolume；可选末端 `OrientationConstraint`（绝对容差，weight=1）；常规规划 20 次尝试/3s，`plan_only` 放宽到 5s。
- **关节目标**：7 关节各 ±0.01rad JointConstraint。
- **笛卡尔执行**：`max_step=5mm`、`jump_threshold=0`、`avoid_collisions` 可调；fraction≈1 才交 JTC 执行。
- **碰撞盒**：BOX 原语 + 增量场景（`scene.is_diff`）。

### 4.2 场景与执行前置（executor）
触发后"四步验证"：**加目标盒(规划场景) → 清 octomap → 等点云重建确认 → 关节稳 → `plan_only` 验证可达**，每步独立超时回退，卡死即放弃该轮并上报。
- **关节稳判定**：0.2s 采样、max-delta<0.01rad 连续 3 次才准规划，规避"从运动中状态起规划 → Invalid Trajectory"。
- **octomap 全生命周期**：清空→重建确认(`insert_settle`)→规划期加盒→回 home 前移除；空闲 10s 周期清一次防残留点云挡规划。

### 4.3 到位执行策略
- **一次到位**：plan_only 已证可达，OMPL 一次规划到最终抓取位姿（含盒规避）。
- **直线接近（精对准模式核心）**：精对准后为不扰动已对准的姿态与高度，走**笛卡尔水平直线**——终点仅替换目标 x/y，**z 与姿态保持当前精对准值**（可按层加抬升量防碰桌面），`avoid_collisions=False`，到位只判 base 系 xy 误差 ≤2cm 连续 3 次；直线不可达自动**降级 OMPL 一次到位**双保险。

### 4.4 底层通路与上下层通信
```
MoveIt 规划结果 → moveit_simple_controller_manager
 → ros2_control JTC(200Hz 插值,mock) → joint_states remap → <ns>/control/joint_states
 → agx_arm_ctrl_single_node（订阅并转发真机）
```
- **控制门**：MoveIt 执行器 `arm/gripper_controller` 的 `follow_joint_trajectory` status 为 `EXECUTING` 才开门（`/control_enable` 放行 `control/*`），否则关门——杜绝规划间隙杂散指令落到 CAN。夹爪通道 `control/gripper_target` 旁路门（专供 GripperClient）。
- **底层指令面**：`control/joint_states`(move_j 平滑 / fast_mode→move_js)、`move_j|p|l|c`、`move_mit`(MIT 直控)；反馈 `feedback/joint_states`(含爪宽/力)、`feedback/tcp_pose`、`feedback/gripper_status`、`feedback/arm_status`。
- **可靠性**：固件版本自动探测与协议切换、失连 5s 自愈重连+重新使能、开机 auto_home；`arm_watchdog` 运行中掉电自动杀栈触发 systemd 重启回 home。

### 4.5 车-臂协议
`/arm/task_command`(层号)、`/arm/release_command`(放物)、`/arm_task_report`(绝对话题 JSON `{command:STOW|PICK|PLACE, success, error_code, message}`)。**上报必在臂收回后**：STOW 为 IDLE∧在 home 时 3s 心跳（"底盘可动"门控）；PICK/PLACE 终态在 `WAIT_RELEASE_CMD` 出口或 `RETURN_HOME→IDLE` flush。错误码：0 成功 / 3 找不到物体 / 5 抓取失败(含空抓) / 7 超时 / 9 控制失败；85s 任务 watchdog 防与调度 90s 超时失步。

## 5. 设计亮点小结

- 决策-执行解耦、两级对准（粗→ArUco 精）收敛快且确定性高；
- **ArUco 判位闸门**：位姿几何不满足即纠偏/重试，不盲目夹取；
- 目标多帧锁定 + 触发竞态消除，抓取不抓"漂移帧"；
- 斜视抓取点用"顶面足迹质心"，比网络 argmax 更稳；
- 先 `plan_only` 后执行 + 关节稳门控 + octomap 生命周期管理，安全可复现；
- 宽度+力联合证据判夹持/防滑，空抓按失败重试；
- 分级回退收臂、点云只挖洞重建、`[TIMING]` 阶段埋点、失连自愈 + watchdog 掉电重启，长时无人值守仍可恢复；
- 配套虚拟组件与 RL 残差精修（patch + 抓取标量，以真实夹爪回报做上下文多臂赌博机在线学习），无硬件即可全链路联调。
